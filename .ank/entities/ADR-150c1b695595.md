title: Git is the source of truth for content, and the hub is authoritative for coordination refs only

constraint: |
  The hub stores refs under refs/ank/* and the objects they name, and never stores, serves or interprets .ank/ files or code.
schema: 4
version: 1

`.ank/` files live in the repository, on the code remote, ratified on the
default branch. The hub owns exactly one thing: the arbitration of coordination
refs for a corpus, and the objects those refs name.

Measured on ank 0.9.0: a claim ref and a proof ref each name a blob. A
completion record names its commit and branch in the blob's text, not as a
parent. So what the store holds is refs and the blobs they name, nothing of the
object graph of the code. The restriction is not a limitation to work around:
it is what keeps the hub replaceable and the repository whole without it.

Lifting the namespace restriction towards full git hosting is a deferred
ambition and would be a superseding decision, not a drift.
