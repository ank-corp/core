The opportunity report puts verifier replay on hub runners in phase 3 and
calls it the single most valuable capability. It is, and it is also a phrase
with nothing under it. This decision orders the work so that the valuable part
(a proof nobody self-reported) arrives early and cheaply, and the expensive
part (hub-side compute) arrives when it is needed.

Why CI first:

- A CI proves that the tests pass on a commit. ank proves that a frozen
  criterion was met by that commit, by that identity, with those verifiers.
  These are different claims, and AnkHub must not rebuild a CI to make the
  second one. Most teams that run many agents already have a CI; the cheap
  independent proof is a job in it that runs the declared verifiers and pushes
  a detached attestation (`ank attest --detached` exists in ank 0.9.0) to the
  hub as `process:ankhub`.
- Hub runners then serve the teams that have no CI, or that want a replay
  independent of their own infrastructure. The same attestation format, the
  same ingestion, one more producer.

Prerequisite in ank: a verifier must declare the environment it runs in, by
content digest, and a proof must record it. Without that, "replayed elsewhere"
is a different experiment, not a replay. Proposed as
https://github.com/haksolot/ank/issues/570. The CI job runs the verifiers in
that declared environment.

What the attestation says: "replayed in <digest>, N times, result X", never
a boolean. Non-deterministic and flaky tests make a failed replay evidence,
not a verdict. Its format is an existing provenance standard (in-toto or
SLSA shape) so that tools outside ank can read it; which one is decided with
the attestation ingestion task.

What stays true: the hub still holds no code (ADR-150c1b695595). A CI job or
a runner fetches the proven commit from the code remote with its own
read-only access; the hub receives the attestation ref, nothing else. When
hub runners do arrive, a verifier is arbitrary code from the repository, so
the sandbox is hostile by default: no network unless the declared environment
names what it needs.

`core` itself is the first project this applies to: its tasks declare
`cargo test --workspace` as verifier, and its proofs are local until its own
CI attests them.
