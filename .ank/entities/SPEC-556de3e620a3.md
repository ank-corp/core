Supersedes SPEC-5a497f765954 after the drift audit of 2026-10-13. Four
corrections, each measured: git protocol v2 has no push; ank 0.9 cannot tell
a hub refusal from a lost race or a dead remote; the ank-side decisions this
phase rests on are open proposals, not shipped ADRs; and "hub as origin" only
works under a precondition the previous spec left unsaid. Everything else is
carried over unchanged.

Phase 1 delivers a remote an unmodified ank 0.9 can be pointed at, plus an
event stream. No new verb.

## Components

| Component | Responsibility |
| --- | --- |
| Ref store (`hub-store`) | Authoritative storage of `refs/ank/*` per corpus and the blobs they name. Atomic compare-and-swap with git `receive-pack` semantics. |
| Git front (`hub-git`) | Smart HTTP and SSH. `ls-refs` and `fetch` over protocol v2; push over receive-pack (protocol v0 with `report-status`, the only push protocol git defines). Serves `refs/ank/*` only; any other ref is refused. |
| Event stream (`hub-events`) | Per-corpus SSE endpoint emitting ref transitions in sequence order, resumable. |
| Tenancy (`hub-tenancy`) | Organisations and corpora, keyed by path, registered with a root commit. |
| Minimal auth (`hub-auth`) | Per-organisation bearer tokens for HTTP, keys for SSH. Identity binding is phase 2. |
| Binary (`ankhub`) | Composes the crates; one data directory; no external service. |

## Addressing

    https://ankhub.com/<org>/<corpus>.git        git remote (HTTP)
    ssh://git@ankhub.com/<org>/<corpus>.git      git remote (SSH)
    https://ankhub.com/<org>/<corpus>/events     event stream (SSE)

A corpus is registered under an organisation with its root commit. The root
commit is a check at registration (no two corpora of one organisation share
one), never the key.

## Ref store semantics

- An update carries old and new object ids and succeeds only if the stored
  value equals old. A multi-ref push is atomic: all or none. Measured on ank
  0.9.0, ank pushes one ref per push with `--force-with-lease=<ref>:<old>`;
  an empty old means "must not exist". Multi-ref atomicity is receive-pack's
  contract and is kept for clients that use it.
- The store holds refs under `refs/ank/*` and the blobs they name, as opaque
  bytes. Claim, proof and completion refs each name a blob; nothing of the
  code's object graph is reachable from them. A push that carries any other
  object kind, or a ref outside the namespace, is refused.
- A write is acknowledged only after it is in the write-ahead log. Recovery
  replays the log: no acknowledged update is lost, no unacknowledged update
  becomes visible.
- Each successful update is assigned a monotonic per-corpus sequence number
  and a receive timestamp from the hub's clock.
- Storage: SQLite in WAL mode for refs and metadata, content-addressed files
  for blobs. Chosen for single-binary self-hosting; revisited only on
  measured need.

## Refusals

Per ADR-604f360549ad. A refused update is an `ng <ref> <reason>` line in
receive-pack's report-status, with a stable reason token: in phase 1,
`held` (compare-and-swap lost) and `namespace` (a ref outside `refs/ank/*`
or an object that is not a blob). `ls-refs` and `fetch` keep answering a
client whose push was just refused, so ank's fallback `ls-remote` succeeds
and the client reads a refusal, never an unreachable remote. A client with
no right to read the corpus is refused at the transport.

## Event stream

    event: ref
    id: <sequence>
    data: {"contract":1,"corpus":"<org>/<corpus>","ref":"refs/ank/claims/TASK-...","old":"<oid>","new":"<oid>","at":"<RFC3339>","seq":<n>}

- Resume with `Last-Event-ID`. The hub retains enough history to resume
  within a bounded window; beyond it, the stream says so and the client
  refetches.
- Ref transitions only, never file contents.
- `contract` versions the payload, consistent with ank's `--json` contract.
- `at` is the hub's receive timestamp: the clock of record for leases once
  ank reads it.

## What the ank side provides

ank is ours. These are decided in `haksolot/ank` and were proposed there as
issues on 2026-10-09; on 2026-10-13 all three are open and none is an ADR in
ank's corpus yet. Phase 1 of the hub is usable by nobody until the first
ships, because the hub holds no code and the code has to live on some other
remote.

1. haksolot/ank#552: a remote named `ank`, when present, carries
   `refs/ank/*`; otherwise `origin`. Code state is still read from `origin`.
2. haksolot/ank#553: `ank watch` subscribes to the event stream when the
   coordination remote advertises one; otherwise it polls as today (every
   60 s by default, measured in `ank-daemon`). Discovery: capability
   advertisement over git protocol v2, default if nothing better is found.
3. haksolot/ank#554: lease expiry computed from the hub's receive timestamp
   when available.
4. The push-refusal reading of ADR-604f360549ad: ank reports a refused push
   by its reason, never as a local win. Not needed for phase 1's own
   refusals, needed before phase 2.

## Acceptance criteria

- An unmodified ank 0.9 with the hub configured as `origin` passes ank's own
  claim, release, done and completion scenarios, **with `default_branch` set
  in `.ank/config.yml`**: ank otherwise resolves the default branch from
  `refs/remotes/origin/HEAD`, which a remote serving no `refs/heads/*`
  cannot provide. This is a test configuration, not a deployment: the code
  of such a corpus lives in the clone alone.
- With #552 shipped in ank, the same scenarios pass with code on GitHub and
  claims on the hub. This criterion is measured when #552 ships and is not
  part of the phase 1 exit task's criterion.
- Race correctness at N = 50 contenders: exactly one winner, every time,
  across 1,000 trials.
- Claim CAS p95 under 100 ms on the same continent. Revised after phase 0 to
  beat the best of GitHub and Entire at every N.
- Event propagation p95 under 500 ms from accepted push to delivery at a
  subscribed `watch`. Measured when #553 ships; until then, the local bound
  of the hub-events task stands in.
- Kill the hub mid-push: on restart, no acknowledged update is lost and no
  unacknowledged update is visible.
- Self-hosting: one binary, one data directory, starts with no external
  service.

## Explicitly out of phase 1

Identity binding, scoped tokens, audit log, web UI, runners, PR gate, peers,
hub-wide scope intersection (the client's signal is already global once all
claims live on one hub), any non-`refs/ank/*` ref, any feature requiring a
new ank verb.
