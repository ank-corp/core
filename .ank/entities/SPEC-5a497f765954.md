Phase 1 delivers a remote an unmodified ank 0.9 can be pointed at, plus an
event stream. No new verb; no change to any verb's refusals.

## Components

| Component | Responsibility |
| --- | --- |
| Ref store (`hub-store`) | Authoritative storage of `refs/ank/*` per corpus and the blobs they name. Atomic compare-and-swap with git `receive-pack` semantics. |
| Git front (`hub-git`) | Smart HTTP (protocol v2) and SSH. Accepts pushes and serves fetches for `refs/ank/*` only; any other ref is refused. |
| Event stream (`hub-events`) | Per-corpus SSE endpoint emitting ref transitions in sequence order, resumable. |
| Tenancy (`hub-tenancy`) | Organisations and corpora, keyed by path, registered with a root commit. |
| Minimal auth (`hub-auth`) | Per-organisation bearer tokens for HTTP, keys for SSH. Identity binding is phase 2. |
| Binary (`ankhub`) | Composes the crates; one data directory; no external service. |

## Addressing

    https://ankhub.com/<org>/<corpus>.git        git remote (HTTP)
    ssh://git@ankhub.com/<org>/<corpus>.git      git remote (SSH)
    https://ankhub.com/<org>/<corpus>/events     event stream (SSE)

A corpus is registered under an organisation with its root commit. The root
commit is a check at registration (no two corpora of one organisation share
one), never the key.

## Ref store semantics

- An update carries old and new object ids and succeeds only if the stored
  value equals old. A multi-ref push is atomic: all or none.
- The store holds refs under `refs/ank/*` and the blobs they name, as opaque
  bytes. Measured on ank 0.9.0, claim, proof and completion refs each name a
  blob; nothing of the code's object graph is reachable from them. A push
  that carries any other object kind, or a ref outside the namespace, is
  refused.
- A write is acknowledged only after it is in the write-ahead log. Recovery
  replays the log: no acknowledged update is lost, no unacknowledged update
  becomes visible.
- Each successful update is assigned a monotonic per-corpus sequence number
  and a receive timestamp from the hub's clock.
- Storage: SQLite in WAL mode for refs and metadata, content-addressed files
  for blobs. Chosen for single-binary self-hosting; revisited only on
  measured need.

## Event stream

    event: ref
    id: <sequence>
    data: {"contract":1,"corpus":"<org>/<corpus>","ref":"refs/ank/claims/TASK-...","old":"<oid>","new":"<oid>","at":"<RFC3339>","seq":<n>}

- Resume with `Last-Event-ID`. The hub retains enough history to resume
  within a bounded window; beyond it, the stream says so and the client
  refetches.
- Ref transitions only, never file contents.
- `contract` versions the payload, consistent with ank's `--json` contract.
- `at` is the hub's receive timestamp: the clock of record for leases once
  ank reads it (ADR in `haksolot/ank`).

## What the ank side provides, decided in haksolot/ank

1. A remote named `ank`, when present, carries `refs/ank/*`; otherwise
   `origin`. Code state is still read from `origin`.
2. `ank watch` subscribes to the event stream when the coordination remote
   advertises one; otherwise it polls as today. Discovery: capability
   advertisement over git protocol v2, default if nothing better is found.
3. Lease expiry computed from the hub's receive timestamp when available.

## Acceptance criteria

- An unmodified ank 0.9 with the hub configured as `origin` passes ank's own
  claim, release, done and completion scenarios.
- With the coordination remote convention shipped in ank, the same scenarios
  pass with code on GitHub and claims on the hub.
- Race correctness at N = 50 contenders: exactly one winner, every time,
  across 1,000 trials.
- Claim CAS p95 under 100 ms on the same continent. Revised after phase 0 to
  beat the best of GitHub and Entire at every N.
- Event propagation p95 under 500 ms from accepted push to delivery at a
  subscribed `watch`. Revised after phase 0 likewise.
- Kill the hub mid-push: on restart, no acknowledged update is lost and no
  unacknowledged update is visible.
- Self-hosting: one binary, one data directory, starts with no external
  service.

## Explicitly out of phase 1

Identity binding, scoped tokens, audit log, web UI, runners, PR gate, peers,
hub-wide scope intersection (the client's signal is already global once all
claims live on one hub), any non-`refs/ank/*` ref, any feature requiring a
new ank verb.
