Amends ADR-ed35e261835d, which keeps its ordering (the project's CI attests
before any hub runner exists) and loses one word: "independent".

What ADR-ed35e261835d took as true: a CI job that runs the declared verifiers
on the proven commit produces "a proof nobody self-reported". What the
repository shows: the CI runs the workflow file of the commit it checks out,
and the verifiers it runs are the ones `.ank/config.yml` declares at that
commit. Both files are in the agent's branch. An agent that edits
`.github/workflows/ci.yml` to print green, or narrows `verifiers:` to a test
that passes, gets an attestation under `process:ankhub` for a commit whose
real verifiers were never run. Nothing in the attestation path as decided
would notice. The CI is independent of the agent's **machine**; it is not
independent of the agent's **commit**, and the second is the one that
matters, because the commit is the thing being proven.

haksolot/ank#570 (a verifier declares the environment it runs in by digest,
and a proof records it) covers the environment. It does not cover the
verifier declaration itself, nor the workflow definition that invokes it.

What makes an attestation independent is a comparison the hub can make:

1. The attestation records three digests: the verifier declaration it ran
   (the `verifiers:` block as the CLI resolved it), the declared environment
   (per #570), and the workflow definition that produced the attestation
   (the workflow file, or the equivalent for another CI).
2. The hub holds no code (ADR-150c1b695595), so it cannot compute what the
   default branch carries. The reference digests reach it the way everything
   else does: the CI job that attests also attests, from a checkout of the
   default branch, the digests of the same three things there. Where the
   default branch's digests equal the proven commit's, the attestation is
   **matched**. Where they differ, it is **unmatched**: stored, visible, and
   not counted as an independent replay.
3. An unmatched attestation is evidence, not a verdict, in the same way a
   failed replay is. A task that legitimately changes the verifiers (adding a
   test suite) produces unmatched attestations until that change is ratified
   on the default branch; the next attestation after the merge matches.

The ank side (an extension to #570, proposed as a comment there): the
attestation record carries the digest of the verifier declaration it ran,
beside the environment digest. The workflow digest is the CI job's to add;
the hub's ingestion defines the field.

What this does not change: hub runners still come after the CI path ships
(ADR-ed35e261835d); the hub still receives attestation refs and never code;
a matched attestation still says "replayed in <digest>, N times, result X",
never a boolean. The PR gate (phase 3) is where "unmatched" becomes a check
a human sees before merging; until then it is a field a reader prints.
